> **개발 기준 문서 / 바이브코딩용**  
> 브랜드: **VIN (Vision Inside)** · 메시지: **Explore to Evolve**  
> 기준 문서: [VIN 포트폴리오 | 화면·인터랙션 기획 (Notion)](https://app.notion.com/p/VIN-3fb164ab02c381c79eb7c3a5efb6f4c8)  
> 작성 기준: 2026-10-27 · 상태: 구현 가이드 v1.0  
> 이 문서는 노션에 명시된 요구사항과 구현을 위한 **제안/기술 결정**을 구분한다. 최종 화면 판단 시 노션의 8개 참고 시안을 우선 확인한다.

## 0. AI 코딩 에이전트에게 가장 먼저 전달할 지시

이 프로젝트는 일반적인 섹션형 포트폴리오가 **아니다**. 하나의 **인디고 3단 서랍장**이 공간적 내비게이션이자 스토리텔링 장치다. Intro의 정면 카메라가 Home의 수직 Top View로 연속 이동한다. 스크롤에 맞춰 1·2·3번째 서랍이 **하나씩** 열리고, 역스크롤하면 같은 경로로 돌아간다.

**필수:**
1. 노션의 화면 순서, 오브제, 인터랙션을 그대로 유지한다. 콘텐츠·이력·연락처·성과를 만들어내지 않는다.
2. 디자인과 UX를 먼저 검증할 수 있도록 **최소 작동 씬**부터 구현한다. 한 번에 전체를 생성하지 않는다.
3. 3D 씬은 **단일 모델/좌표계**를 사용한다. 장면마다 서랍장을 새로 로드하거나 다른 디자인으로 교체하지 않는다.
4. 스크롤 구간, 클릭으로 열린 집중 화면, 라우트 상태를 **하나의 상태 설계**로 관리한다.
5. 모든 주요 행동에는 클릭·탭·키보드 대체 조작을 제공한다. 모바일에서는 문서 읽기가 인터랙션보다 우선이다.
6. 실제 자산/원문이 없다면 명시적으로 `TODO`를 남기고 플레이스홀더를 사용한다.
7. 매 작업 단계 끝에 구현 항목, 미구현 항목, 실행 방법, 오류/변경 파일을 보고한다.

## 1. 프로젝트 의도와 성공 기준

- **목적:** UX/UI 및 프로덕트 디자이너 지원을 위한 개인 포트폴리오. 사용자가 '발견하고 열어보는' 탐색 경험으로 작업의 맥락을 이해한다.
- **사용자:** 채용 담당자·실무 디자이너·교수·협업 제안자.
- **핵심 경험:** `발견 → 명함 탐색 → About → Work → Contact`.
- **브랜드 어조:** 미니멀, 에디토리얼, 정돈된 타이포그래피. 개성은 3D 오브제와 동작에서 나타내며, 본문 가독성을 희생하지 않는다.
- **성공 조건:** (1) 순방향/역방향 복원이 정확함 (2) 프로젝트 상세를 쉽게 열고 읽을 수 있음 (3) 모바일에서도 핵심 정보 접근 가능 (4) 저사양에서 안정적 (5) 허위 콘텐츠 없음.

상단 링크는 `HOME · ABOUT · WORK · CONTACT`를 유지한다. `INTRO` 별도 상단 메뉴는 원안에 없다. 3개의 서랍 중 **동시에 열리는 것은 하나뿐**이다. Home에서 명함을 본 후 Contact에서 **같은 명함**을 다시 사용한다.

### 2.1 노션 시안 해석 시 주의
- 노션 첨부 이미지는 **구도와 분위기 참고 시안**이다. 텍스트/빈 이력서/프로젝트 1·2 같은 플레이스홀더는 실제 콘텐츠가 아니다.
- Intro 이미지와 후속 이미지의 서랍장 외형이 다른 경우, **최신 인디고 3단 서랍장** 외형을 기준으로 연속 모델 하나를 제작한다.
- Work 폴더는 노션의 배치와 선택 반응을 참고하되, 최종 그래픽은 간결한 일러스트 방향으로 정리한다.
- 원안 흐름은 `Intro → Home → About → Work → Contact`. 이전 구상의 ‘3단 서랍 = 스킬 오브제’ 안을 혼합하지 않는다. **최신 3번째 서랍은 Contact 전화기**이다.

## 4. 권장 기술 스택 (구현 제안)

- **Vite + React + TypeScript**: 기본 앱/컴포넌트 구조.
- **Three.js + @react-three/fiber + @react-three/drei**: 단일 3D WebGL 씬, 카메라/오브제 렌더링, GLB 로딩.
- **GSAP + ScrollTrigger**: 스크롤과 카메라/서랍 오픈 진행률 매핑. 현재 프로젝트에서 설치 가능한 호환 버전으로 고정하고 버전을 기록한다.
- **Zustand (선택):** 클릭 집중 화면/명함 앞뒤/현재 프로젝트 등 작은 UI 상태. 단일 React 상태로 충분하면 도입하지 않는다.
- **React Router (선택):** 상세 프로젝트를 공유/북마크 가능하게 만들 경우 `/work/:slug`. 기본 씬 상태와 라우트 동기화는 별도 처리.
- **CSS Modules / 일반 CSS**: 레이아웃·반응형·UI 토큰. 인터페이스가 단순하면 불필요한 UI 프레임워크를 추가하지 않는다.
- 권장 개발 방식: 로컬 `npm install` → `npm run dev`, 배포 전 `npm run build`/`npm run preview` 테스트.

> **중요:** 이 문서는 패키지의 구체적인 최신 버전을 주장하지 않는다. 설치 시 React/R3F/Three/Drei/GSAP 호환성을 확인해 `package-lock.json`에 잠근다. 브라우저에서 GLB가 정상 로드되는지 반드시 검사한다.

## 6. 3D 자산 명세

### 6.1 최소 씬 그래프 (개발용 계약)

```text
PortfolioScene
├─ EnvironmentLights
├─ CabinetRoot (고정 월드 좌표)
│  ├─ CabinetBody
│  ├─ CabinetTop
│  ├─ Drawer01_Pivot (슬라이드: 로컬 서랍 오픈 축)
│  │  └─ ResumeAnchor
│  ├─ Drawer02_Pivot
│  │  └─ ProjectFilesAnchor
│  └─ Drawer03_Pivot
│     └─ TelephoneAnchor
├─ BusinessCardAnchor (Home 상판 위)
└─ CameraRig
```

- `cabinet.glb`는 **body / drawer1 / drawer2 / drawer3** 등을 독립 노드로 분리해야 한다. 하나의 합쳐진 메시면 실제 서랍 오픈 애니메이션이 어려움.
- 서랍을 당기는 축은 제작 모델 좌표계에 맞게 설정. 이 문서의 예시 축값을 맹목적으로 적용하지 않는다.
- 3단 모두 **닫힌 위치 = progress 0, 열린 위치 = progress 1**로 정규화한다. 방향 및 거리 상수는 구성 파일에서 관리.
- 파일·이력서·전화기는 별도 노드로 배치, 부모 서랍 이동에 따라 함께 움직임.
- `cabinet.glb`가 없는 초기 단계에서는 박스/평면으로 제작한 **기능 테스트용 임시 모델**을 사용. 임시 모델을 최종 비주얼이라고 보고하지 않는다.
- 모바일/저사양에서 사용할 정적 대체 이미지 4장 이상 (Intro/Home/About/Work/Contact 중 필요한 상태)을 추후 추출한다.

## 7. 스크롤·카메라 설계 (구현 제안)

### 7.1 카메라 규칙

- **Intro:** 캐비닛 정면, 아래쪽 중앙 배치. 서랍장 전체가 보인다.
- **Home:** 카메라 위치와 `lookAt`을 함께 보간해 상판의 수직 Top View로 전환한다. 단순 오브제 회전으로 카메라 이동을 흉내 내지 않는다.
- **About/Work/Contact:** Top View 기반으로 해당 열린 서랍의 내용이 화면 중심에 오게 카메라 타깃을 미세 조정한다.
- 이동은 하나의 연속 카메라 경로. 컷, 씬 재생성, 갑작스러운 FOV 변화 금지.
- 카메라 위치/회전/타깃은 모델 치수에 따라 **실측 후 튜닝할 설정값**으로 분리한다.

### 7.2 권장 진행률 구간 (최초 프로토타입용, 확정 타이밍 아님)

| 전체 스크롤 비율 | 화면 상태 | 애니메이션 |
|---|---|---|
| 0–0.12 | INTRO | 타이포 시퀀스 및 정면 캐비닛 |
| 0.12–0.25 | HOME | 정면→Top View, 명함 위치 확인 |
| 0.25–0.34 | CARD_FOCUS | 명함 확대, 배경 흐림 (스크롤 진입 시) |
| 0.34–0.47 | ABOUT | 첫째 서랍 열기 |
| 0.47–0.55 | RESUME_FOCUS | 이력서 집중 |
| 0.55–0.70 | WORK | 첫째 닫고 둘째 열기, 파일 순차 강조 |
| 0.70–0.82 | PROJECT_PREVIEW | 선택 파일 강조·집중(선택 상세는 별도 UI) |
| 0.82–1.00 | CONTACT | 둘째 닫고 셋째 열기, 전화기 반응/명함 재등장 |

실제 스크롤 체감은 테스트 후 수정. **문서 내부 스크롤과 배경 씬 스크롤이 동시에 반응하면 실패**다.

### 7.3 상태 모델

```ts
type Stage =
  | 'intro' | 'home' | 'cardFocus'
  | 'about' | 'resumeFocus'
  | 'work' | 'projectPreview' | 'contact';

type Overlay =
  | null
  | { type: 'card'; flipped: boolean }
  | { type: 'resume' }
  | { type: 'project'; slug: 'packit' | 'printcafe' | 'le-labo' };

type ExperienceState = {
  stage: Stage;
  overlay: Overlay;
  reducedMotion: boolean;
};
```

**상태 불변 조건:**
- 스크롤은 `stage`와 3D 속성을 결정한다. 모달은 `overlay`가 결정한다. 두 체계를 별개로 두되 충돌하지 않게 한다.
- 사용자가 오브제를 클릭하면 해당 Overlay가 열린다. Overlay가 열려 있는 동안 배경 스크롤 입력은 잠금 처리한다.
- Overlay 닫기(Escape, 닫기 버튼) 시 기존 `stage`와 스크롤 위치를 복구한다.
- 스크롤로 Focus 구간에 들어왔을 때의 확대는 **기본 프리뷰**, 클릭으로 연 상세 문서는 **별도 Overlay**로 분리해 스크롤 락 충돌 방지. 본 설계가 원안의 클릭/스크롤 확대 두 동작을 동시에 안정적으로 구현하기 위한 기술 제안이다.
- 상단 섹션 메뉴는 해당 앵커 구간으로 부드럽게 이동. 이동 중 기존 오버레이를 닫는다.
- 뒤로 스크롤하면 이전 서랍이 다시 열려야 하며, 이전에 열려 있던 다음 서랍이 남아 있으면 실패.

### 7.4 ScrollTrigger 개발 주의

- **한 번만 초기화**하고 컴포넌트 unmount 시 모든 timeline/ScrollTrigger 이벤트를 정리한다(`gsap.context(...).revert()` 등).
- React 개발 모드 StrictMode에서도 트리거 중복 생성/서랍 떨림이 없어야 한다.
- `scrub`을 사용하는 구간은 스크롤 방향에 관계없이 **절대 진행률**에서 3D 속성을 계산한다.
- `pin` 중 스크롤 높이를 변경하거나 오버레이 안에서 `ScrollTrigger.refresh()`를 무한 호출하지 않는다.
- 화면 리사이즈, 폰트/GLB 로딩 완료 후 필요한 시점에만 refresh.
- 카메라와 drawer 애니메이션을 매 프레임 React `setState`로 갱신하지 말고 ref/GSAP 또는 프레임 루프를 사용한다.

## 8. 화면별 인터랙션 상세

### 8.1 Intro
- 진입: 흰 화면, `PARK SU VIN`, `VISION INSIDE`, `VIN` 타이포 순차 전환.
- 타이포가 끝나면 인디고 캐비닛과 연결된 구도가 보인다. 애니메이션 도중에도 스크롤 사용 가능하게 설계.
- 장식 애니메이션이 내용 접근을 막지 않게 `Skip motion` 또는 `Skip to Work` 접근 경로 고려(추가 UX 제안).

### 8.2 Home / 명함
- Top View의 상판 위 명함. 포인터 Hover에서는 미세 lift/회전/테두리 힌트.
- 클릭/탭/Enter/Space: 명함을 확대 → 중심 고정 → 뒤의 상판만 흐림.
- 명함 뒤집기: 앞/뒤 전환. 텍스트는 실제 연락처 확보 전 `정보 확인 중` 플레이스홀더.
- 닫기/ESC: 뒤집기 상태 초기화 후 상판의 원래 위치로 복귀.

### 8.3 About / 이력서
- 첫째 서랍이 앞으로 이동. Top View로 종이 노출.
- 이력서는 클릭/탭으로 큰 읽기 화면. 가독성 우선: **HTML 또는 접근 가능한 PDF 뷰어 형태를 검토**하되 PDF 제공 시 본문 HTML 대체 수단 마련.
- 배경만 흐리게 하고 본문은 선명하게 렌더링. 모바일 문서 내부 스크롤 허용.
- 실제 학력·경력·역할을 임의 생성하거나 자동으로 성과 수치를 넣지 않는다.

### 8.4 Work / 프로젝트 파일
- 두번째 서랍 안 파일 라벨: **PACKIT / PRINTCAFE / LE LABO**. 추가 프로젝트는 기획 변경 후 반영.
- 스크롤 중 파일을 순차 강조하되, 선택할 수 있는 모든 파일은 상시 클릭 가능해야 한다.
- Hover/Focus: 해당 인덱스 탭 강조. 클릭/탭: 파일 중심 확대 → 프로젝트 상세 열기.
- 상세 페이지에는 프로젝트 이름, 배경/기간/팀과 역할, 문제/목표, 조사 근거, 핵심 판단, IA/Flow, 주요 화면, 개선, 결과/배운 점/한계를 실제 자료로 작성.
- `Previous / Next`, `Back to files` 버튼. 프로젝트 간 이동해도 오버레이와 카메라 상태가 일치해야 한다.
- 긴 사례 연구는 전체 내용을 3D 평면에 넣지 말고 **접근 가능한 HTML 콘텐츠 레이어**에 렌더.

### 8.5 Contact / 전화기
- 세번째 서랍에 아날로그 다이얼 전화기.
- 수화기에 '띠링, 띠링' 반응을 **시각적 모션으로** 표현: 작은 회전/진동(절제), 레이블 또는 반응 표시.
- 클릭/탭 시 Home의 **동일한 명함 UI/데이터**를 재사용해 중앙 확대; 뒤집으면 연락처.
- 소리는 필수 기능이 아니며 기본은 **무음**. 추후 소리를 도입하면 사용자 제스처 이후에만 재생하고 끄기 제공.

## 9. 반응형·접근성

- Desktop: 마우스/트랙패드 스크롤 + hover + 직접 선택 모두 지원.
- Tablet/Phone: hover에 의존하지 않음. 터치 버튼 크기 최소 약 44px 권장, 화면 안에서 명함·문서·프로젝트가 잘리지 않아야 함.
- 모바일: WebGL 품질을 낮추거나 **정적 장면 + DOM 패널**로 단계적 강등. 정적 대체 경로에서도 About/Work/Contact 접근 가능.
- 모든 오브젝트에 대응하는 DOM 버튼을 제공. `tabIndex`만 부여한 3D Mesh를 키보드 내비게이션 전체로 간주하지 말 것.
- Overlay: `role=dialog`, 적절한 이름, 초기 포커스 이동, 내부 포커스 관리, 닫기 후 열었던 버튼으로 포커스 복귀.
- 키보드: `Tab/Shift+Tab`, `Enter/Space`, `Escape`. 3D를 사용하지 않고도 정보 열람 가능.
- `prefers-reduced-motion: reduce`: 카메라 전환은 순간 이동 또는 단순한 페이드로 대체, 전화기 진동 제거, 강한 시차감 제거.
- 텍스트/배경 대비 확인, 이미지 대체 텍스트, 명확한 메뉴 현재 위치.

## 10. 성능·품질 예산 (제안, 실제 측정 후 조정)

- 3D 모델은 필요한 것만 로드. GLB 노드 이름·재질 재사용·텍스처 크기 최적화.
- WebGL 초기 진입 실패 시 빈 흰 화면 대신 **명확한 대체 네비게이션과 콘텐츠**를 즉시 제공.
- 가능하면 첫 화면의 렌더 비용을 절제하고, 후속 프로젝트 이미지는 지연 로딩.
- 성능 목표(테스트 기준): 데스크톱 일반 환경에서 자연스러운 60fps를 지향, 중급 모바일에서는 30fps 이상의 사용성 지향. 실제 기기 측정 전 보장값으로 표기하지 않음.
- 동일 씬에서 여러 빛/과한 후처리/고해상도 그림자 남용 금지.
- DPR은 기기별 상한을 두고 조절. 배경 정지 시 렌더링 최소화 가능성을 검토.
- 배포 전 Lighthouse 접근성/성능 및 DevTools performance, 휴대폰 실기기 테스트.

## 14. AI가 임의로 바꾸면 안 되는 사항

1. 서랍 3개를 3개의 독립 페이지나 다른 가구로 대체하지 말 것.
2. Intro/Home을 점프컷으로 전환하지 말 것.
3. 3번째 서랍을 Skills 서랍으로 바꾸지 말 것. **현재 Contact 전화기**임.
4. `PACKIT / PRINTCAFE / LE LABO` 외 프로젝트를 임의 추가하지 말 것.
5. 프로젝트 정보를 만들거나 가짜 연락처/이력서 텍스트를 완성하지 말 것.
6. 모든 텍스트를 WebGL 텍스처에 넣어 읽기 어렵게 만들지 말 것.
7. 모달이 열릴 때 서랍이 동시에 움직이거나 배경 스크롤이 중첩되지 않게 할 것.
8. 스크롤 아래로만 맞추고 위로 되돌리는 동작을 생략하지 말 것.
9. 멋을 위한 파티클·블룸·과도한 빛·랜덤 오브제를 추가하지 말 것.
10. 현재 노션 기획과 충돌하는 변경은 먼저 '제안'으로 구분해 보고할 것.
